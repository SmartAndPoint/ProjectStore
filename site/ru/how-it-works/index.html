.projectstore / метод / 1

Цикл с независимой проверкой внутри.

Агенты быстро пишут код и так же быстро пересматривают решённое: каждая новая сессия начинает с нуля. Лечится это не более умным агентом. Лечится циклом «собрать контекст → действовать → проверить», который идёт над проектом, а не только над кодом.

Цикл

Восемь шагов. Два из них — проверки агентом, который не писал черновик.

Агенты

6 агентов. Всем, кроме одного, разрешено только читать.

Советники проверяют, планируют и наводят порядок, но ничего не меняют. Один клерк сохраняет только то, что вы одобрили, и только после вашего «да».

criticтолько чтение · независимый

Когда написан или изменён ADR, спека, эпик, стори или дизайн

Ищет слабые места, сверяет каждое утверждение с источником и спрашивает, как план может провалиться. Без лести.

opus · max
plannerтолько чтение · независимый

До начала работы над стори (story plan)

Смотрит, где в коде живут прошлые эпики. Говорит, где место изменению, что переиспользовать, чего опасаться и в каком порядке работать.

opus · max
reviewerтолько чтение · независимый

После кода, до коммита или story close

Просит подтверждение по каждому критерию приёмки, включая критерии спеки. Затем проверяет корректность, регрессии и тесты.

opus · max
librarianтолько чтение · предлагает

Время от времени, перед релизами, после быстрого роста vault

Находит то, что не поймать правилом: исследования, которые противоречат принятому ADR, дубликаты, недостающие ссылки, файлы, которые пора убрать в архив.

opus · max
archaeologistтолько чтение · предлагает

Один раз, после привязки существующей кодовой базы

Находит решения, которые никто не записал: в коде, конфигах и истории git. Предлагает оформить их в ADR, с доказательствами.

opus · max
clerkпишет · после вашего «да»

Только в рамках команды, только после вашего «да»

Сохраняет ровно то, что вы одобрили, и ничего больше. Затем пересобирает доску и запускает проверки. Ничего не пишет от себя и ничего не спрашивает.

sonnet · max

Модели по умолчанию — для Claude Code. В Codex каждая роль — это одноимённый скилл, который просит Codex её запустить, например $projectstore-critic для критика; роль использует модель сессии, если вы не задали другую.

Защитные механизмы

Всё держится на механизмах, а не на дисциплине.

Нет стори — напоминание

Агенту, который начал править код без открытой стори, напоминают открыть её. Изменение размером с фичу начинается в vault.

Пометка «без ревью» остаётся

Артефакт, которому нужно ревью, остаётся с review_status: pending, пока не применены итоги проверки критиком. «Ещё без ревью» — это состояние, которое читают инструменты, а не то, что кто-то должен помнить.

Doctor без ИИ

doctor детерминированно проверяет механическую согласованность vault. В CI он работает без агента и без токенов.

Куда смотреть — генерируется

graph.md хранит связи каждого артефакта в обе стороны; code-map.md говорит, где живёт код каждого эпика. Перед архитектурным выбором агента сначала отправляют к индексу ADR.

После /compact vault возвращается

В Claude Code после /compact, запущенного вами, сессия снова начинается со сводки по vault и с файлов vault, которые разговор затрагивал до сжатия.

Вторую сессию предупреждают

Сессия, которая стартует, пока другая работает с тем же vault, открывается с предупреждением о нескольких сессиях: сначала поищите, потом создавайте новое.

«Готово» значит «доказано»

Стори закрывается с подтверждением под каждым критерием.

Ещё до кода планировщик сказал, где место изменению, и план попал в стори после вашего «да»; после кода ревьюер сверил диф с каждым критерием. Каждая строка подтверждения — это тест, выполненная команда или строка кода.

Эти записи может прочитать любой агент, с плагином или без: через CLI, который отвечает JSON и не тратит токены, или через 8 инструментов MCP-сервера, доступных только для чтения.

Оговорки

Оговорки

  • Цикл стоит токенов: черновики, критик и ревьюер работают на модели, за которую вы и так платите. Замеры — в README.
  • Критик и ревьюер в Claude Code — отдельные агенты с чистым контекстом. В Codex эти роли — скиллы.
  • ProjectStore — это общий контекст проекта и способ работы. Это не оркестратор агентов: запуск агентов — задача вашего harness.
