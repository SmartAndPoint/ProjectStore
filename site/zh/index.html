安装工作原理为何有效一个 vault，多人协作

# 今天 vibe coding。明天就是遗留代码。# 我们进行到哪了？——每个新会话都要再问一遍。# 编程智能体会遗忘——关闭、压缩、换工具，“为什么”就丢了。

智能体写代码，ProjectStore 留记录。

决定了什么、进行中的是什么、检查过什么——以 git 中经过评审的 Markdown 保存，任何智能体和任何能访问仓库的人都能读。

02 / 直接说就行

无需学习命令。直接说就行。

说出你想要什么。智能体运行工作流，展示每份草稿，并先问再写。下面的场景来自 Claude Code；在 Codex 中，同样的流程是实验性的。

1决策

决定一次，“为什么”留下来。

一个决策会连同被否决的备选方案一起写成 ADR。没有你的“是”，什么都不会写入；写入之后，由一个上下文全新的 critic 来评审。

2规划

计划附带验收标准。

缺口在还只是句子的时候就被发现，而不是等它变成 bug。

3构建

完成意味着有证明。

planner 指出改动应该放在哪里。story 关闭之前，reviewer 要求每条验收标准都有证据。

4下一次会话

明天从看板开始。

新会话一开始就列出进行中的工作。说出一个 story，智能体就从文件里读取它的计划和清单。

设置也只是一句话。

04 / 它的定位

不是智能体记忆，也不是 spec 流水线。
项目工件。

编程智能体身边有三类工具。每一类回答的是不同的问题。

类别它回答的问题示例
智能体记忆这个智能体记得什么？Mem0、Zep，以及 Codex 和 Claude Code 的记忆功能
指令文件智能体在这里应当如何行事？CLAUDE.md、AGENTS.md、规则、steering 文件
Spec 驱动的工具这项改动怎么实现？Spec Kit、Kiro、OpenSpec、BMAD
ProjectStore项目决定了什么，哪些工作正在进行，又是否经过检查？项目工件——ADR、spec、epic、story、看板——带着状态、日期和链接，存放在 git 中。每一份在 ProjectStore 写入之前都由人批准；上下文全新的 critic 按规则评审它。

决策日志、校验器、会话开始时的概况、独立评审，这些在别的工具里各自都有。ProjectStore 增加的，是让它们全部建立在同一份相互关联的记录之上。

05 / 落在磁盘上的内容

纯 Markdown。放在它自己的 git 仓库里。

06 / 单人或团队

一个 vault。多个会话、多个人、多个智能体。

多个会话，同一个 vault

两个智能体或两个人同时在同一个 vault 中工作，是常态。每个会话都知道其他会话的存在，几条简单的规则让它们互不干扰。

每个人看到的都不只是自己那一部分。

开发者、技术负责人和 QA 基于同一套决策和标准工作。没有智能体的人只需要 GitHub 或一个 Markdown 编辑器，因为这些都只是普通文件。

契约共享，工作分区。

在同一个项目里，API、Web 和平台团队基于共享的 ADR 和 spec，各自推进自己的 epic。共享契约的变更，会在评审中与使用它的团队一起讨论。ProjectStore 会显示哪些 story 依赖它。

执行者不同，依据相同。

规划者读决策和代码地图。实现者读 story 和 spec。评审者读 diff 和标准。每一方拿到的是自己需要的上下文，而不是别人会话的全部历史。在同一个 vault 上工作的会话会互相提醒。

07 / 方法、证据与问题

这一套，行业早就发明了。
智能体让它不再昂贵。

ADR、评审、待办池、验收标准、从目标到代码的关联。成熟的工程团队这样工作已有二十年。这些都不是 ProjectStore 发明的。

  1. 1969RFC：决策被写下来并编号，然后公开讨论。
  2. 1992DO-178B：在航空电子领域，每条需求都必须关联到代码和测试。
  3. 1995Scrum：工作成为待办列表，有序且可见。
  4. 1999XP：用户故事，以及说明何时算完成的验收标准。
  5. 2007用于软件开发的看板：显示哪些工作正在进行。
  6. 2011ADR，Michael Nygard：每个架构决策一个简短的文件。
  7. 现在编程智能体：每一步只需几分钟。没有这些工件，每个会话都从空白开始。

这是一个记忆插件吗？

不是。记忆插件记住的是智能体说过什么。ProjectStore 记录的是项目决定了什么，形式是经过评审、带状态和日期的文档。之后的新工作都以这些文档为依据。换智能体、换机器或换队友时，差别就显现出来了：记忆属于某个智能体、某个用户或某台机器，即使是存放在 git 里的记忆，也仍然是智能体自己的笔记；vault 则是项目的记录——经过批准、经过评审、带有状态——并通过 git 流转。

需要 Obsidian 吗？

不需要。vault 就是一个装着 Markdown 文件的普通文件夹。可以在编辑器里打开、在 GitHub 上浏览；如果喜欢 Obsidian 的关系图谱和看板，也可以用它。没有插件，这些文件照样可读。

它会不经询问就写入吗？

不会。每个新文件或每次编辑都会先展示给你，附上路径和完整内容，然后等待“是”“保存前编辑”或“否”。在一旁观察对话的辅助程序只会建议命令。唯一能写入的智能体 clerk 在你说“是”之后运行，一字不差地保存你批准的内容。

卸载之后还剩下什么？

你的 vault 原封不动：它是独立 git 仓库里的纯 Markdown。项目的绑定和团队的智能体模型也会保留，重新安装时会找到它们。Codex 插件是为本机所有项目注册的，所以移除它是单独的一步。如何卸载
