Die Branche hat das längst erfunden.
Agenten haben es günstig gemacht.

ADRs, Reviews, ein Backlog, Abnahmekriterien, Verknüpfungen vom Ziel bis zum Code. Reife Engineering-Teams arbeiten seit zwanzig Jahren so. ProjectStore erfindet nichts davon.

Woher jedes Stück kommt

Woher jedes Stück kommt

  1. 1969RFCs: Entscheidungen, aufgeschrieben und nummeriert, dann offen diskutiert.
  2. 1992DO-178B: In der Avionik muss jede Anforderung auf Code und auf einen Test zurückführbar sein.
  3. 1995Scrum: die Arbeit als Backlog, geordnet und sichtbar.
  4. 1999XP: User Stories und Abnahmekriterien, die sagen, wann eine fertig ist.
  5. 2007Kanban für Software: ein Board, das zeigt, was in Arbeit ist.
  6. 2011ADRs, Michael Nygard: eine kurze Datei pro Architekturentscheidung.
  7. jetztCoding-Agenten: Jeder Schritt dauert Minuten. Ohne die Artefakte beginnt jede Sitzung leer.
Was die Artefakte leisten

Ein Projekt, viele Hände. Dieselbe Grundlage für alle.

Ein ADR hält fest, was entschieden und was verworfen wurde. Eine Spec sagt, wie es funktionieren muss. Ein Epic und seine Stories sagen, was gebaut wird und wann jeder Teil fertig ist. Das Board zeigt, was gerade läuft.

Mit ihnen starten ein Entwickler, der morgen dazukommt, ein Reviewer aus einem anderen Team und ein Agent in einer frischen Sitzung alle mit dem Wissen der ersten Person. Darum pflegen Teams, die große Systeme bauen, diese Dokumente seit Jahrzehnten.

Der teure Teil

Der Prozess war immer wertvoll. Teuer war, dass Menschen jeden Schritt selbst ausführten.

Der Prozess funktioniert. Seine Dokumente sind das Wertvollste, was einem Unternehmen nach einem Projekt bleibt: warum das System so gebaut ist, was als fertig galt, wo jedes Feature im Code liegt. Aber wenn Menschen ihn von Hand betreiben, ist er langsam. Ein ADR zu schreiben kostet einen Nachmittag, bis zum Review vergeht eine Woche. Dokumente hinken dem Code hinterher. Das Board passt nicht mehr zur Realität. Also kürzen Teams ab, und „agil“ wird zur Ausrede, nichts aufzuschreiben.

Fehlen die Artefakte, sieht es bei Menschen und Agenten gleich aus: Geklärtes kommt wieder hoch, niemand kann sagen, warum der Code so ist, wie er ist, und jeder Neue fängt mit Raten an.

Bei Agenten ist es umgekehrt. Ein ADR schreiben, ein Epic in Stories zerlegen oder einen Diff gegen Kriterien prüfen: Das dauert bei einem Agenten Minuten, nicht Tage. Was einem Agenten fehlt, bekommen Menschen gratis: ein Gedächtnis über Sitzungen hinweg, Kontext, den sie mit Kollegen teilen, die Verbindung vom Ziel zum Code. Jede neue Sitzung beginnt leer und entscheidet neu, was längst geklärt war.

Prozess der Menschen+Tempo der Agenten=ProjectStore

ProjectStore bringt beides zusammen. Die Geschwindigkeit von Agenten macht den alten Prozess zum ersten Mal günstig. Die Dokumente dieses Prozesses liegen als Dateien neben dem Code und geben Agenten, was sie nie hatten: den Kontext des Projekts, verknüpft nach oben mit den Zielen und nach unten mit dem Code. Jeden Schritt reviewt laut Arbeitsregel ein zweiter Agent, der den Entwurf nicht geschrieben hat. Geschwindigkeit bekommt ein Gedächtnis, und das Gedächtnis eine Prüfung.

Die Verknüpfungen stehen im Kopf jeder Datei, und der Nachweis ist eine Zeile unter jedem Abnahmekriterium. All das trägt der Agent bei der Arbeit ein. Die Link-Map zeigt, womit jedes Dokument verbunden ist. Die Code-Map zeigt, wo der Code jedes Epics liegt. Eine neue Sitzung, ein neues Modell oder ein neuer Kollege startet von dieser Kette aus, nicht bei null.
