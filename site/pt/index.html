01 / Instalar

# Vibe-coded hoje. Legado amanhã.# Onde estamos? — toda sessão nova pergunta de novo.# Agentes de programação esquecem — fechou, compactou, trocou de ferramenta, e o porquê some.

Seu agente escreve o código. O ProjectStore guarda o registro.

O que foi decidido, o que está em andamento, o que foi verificado — como Markdown revisado no git, legível por qualquer agente e por quem tiver o repositório.

um terminal no seu projeto, fora do agenteClaude Code · supportedCodex · experimental
~/your-project $
npx projectstore setup
▍
  • Ele pergunta onde fica o vault, mostra um plano e pede confirmação uma vez.
  • Depois, reinicie o agente; o Codex pede que você aprove os hooks dele uma vez.
  • Node.js 20+ · npm para o Codex · macOS ou Linux
ou peça ao seu agente: Claude Code · Codex · OpenCode, Cursor e outros agentes

No Claude Code, este prompt adiciona o marketplace git e instala a partir dele; ative a atualização automática dele em /plugin. No Codex, em vez disso, rode o comando acima: dentro de uma sessão, a instalação espera por um terminal. Os outros agentes ainda não têm plugin; eles leem o mesmo vault pelos arquivos, pela CLI e pelo MCP.

Install the projectstore plugin from https://github.com/SmartAndPoint/ProjectStore and set it up for this project.
02 / Depois, é só conversar

Sem comandos para aprender. É só conversar.

Diga o que você quer. O agente roda o fluxo, mostra cada rascunho e pergunta antes de gravar. As cenas abaixo são do Claude Code; no Codex o mesmo fluxo é experimental.

1Decidir

Decida uma vez. O porquê fica.

Uma decisão vira um ADR com as alternativas rejeitadas. Nada é gravado sem o seu sim, e um critic de contexto limpo o revisa depois.

2Planejar

Planos vêm com critérios de aceitação.

As lacunas são detectadas enquanto ainda são frases, não bugs.

3Construir

Pronto quer dizer provado.

O planner diz onde a mudança deve ficar. O reviewer pede evidência para cada critério de aceitação antes de a história fechar.

4A próxima sessão

Amanhã começa pelo quadro.

Uma sessão nova abre com o que está em andamento. Cite uma história, e o agente lê o plano e a lista de verificação direto do arquivo.

Configurar também é uma frase.

a faixaClaude Code · experimental

“Mostre o projeto acima do meu prompt.”

O épico em que você está, quanto já avançou, o objetivo dele, a sua história e o agente trabalhando — acima do prompt, enquanto você trabalha. Enquanto a faixa aparece, a linha de status sai da frente.

modelosClaude Code · Codex experimental, só modelos

o agente executa:

sua própria skillClaude Code · Codex (experimental): arquivos e a CLI

“Escreva uma skill: antes de um release, liste as histórias que não estão concluídas e os ADRs que ainda esperam revisão.”

Uma skill comum que lê o registro: Markdown puro com frontmatter, ou as 8 ferramentas MCP somente leitura.

Todas as configurações, a partir de um terminal:
npx projectstore configure

Para atualizar ou remover, veja Upgrading e Uninstalling no README. A remoção mantém o vault.

04 / Onde ele se encaixa

Não é memória de agente. Nem um pipeline de specs.
É o registro do projeto.

Três tipos de ferramenta ficam ao lado de um agente de programação. Cada um responde a uma pergunta diferente.

TipoA pergunta que respondeExemplos
Memória de agenteDo que este agente se lembra?Mem0, Zep, memória do Codex e do Claude Code
Arquivos de instruçõesComo um agente deve se comportar aqui?CLAUDE.md, AGENTS.md, regras, arquivos de steering
Ferramentas orientadas a specsComo construímos esta mudança?Spec Kit, Kiro, OpenSpec, BMAD
ProjectStoreO que o projeto decidiu? O que está em andamento? E foi verificado?Decisões, specs e itens de trabalho com status, data e vínculos, no git. Uma pessoa aprova cada um antes de o ProjectStore gravá-lo, e a regra é que um critic de contexto limpo o revise.

Logs de decisões, validadores, orientação no início da sessão e revisão independente: cada um já existe em outro lugar. O que o ProjectStore acrescenta é tudo isso sobre um único registro interligado.

06 / Sozinho ou em equipe

Um vault. Muitas sessões, pessoas e agentes.

Várias sessões, um vault

Dois agentes ou duas pessoas no mesmo vault ao mesmo tempo é algo normal. Cada sessão sabe das outras, e algumas regras simples evitam que uma atrapalhe a outra.

Todos enxergam mais do que a própria parte.

O desenvolvedor, o tech lead e o QA trabalham a partir das mesmas decisões e dos mesmos critérios. Quem não usa agente só precisa do GitHub ou de um editor de Markdown: são apenas arquivos.

Contratos compartilhados. Áreas de trabalho separadas.

Em um mesmo projeto, as equipes de API, Web e Plataforma conduzem seus próprios épicos com base em ADRs e specs compartilhados. Uma mudança em um contrato compartilhado é discutida na revisão com as equipes que o usam. O ProjectStore mostra quais histórias dependem dele.

Executores diferentes. Base comum.

O planejador lê as decisões e o mapa de código. O implementador lê a história e a spec. O revisor lê o diff e os critérios. Cada um recebe o contexto de que precisa, não todo o histórico da sessão de outro. Sessões no mesmo vault avisam umas às outras.

É um plugin de memória?

Não. Um plugin de memória lembra o que o agente disse. O ProjectStore registra o que o projeto decidiu, em documentos revisados, com status e data. O trabalho novo passa por esses documentos. A diferença aparece quando você troca de agente, de máquina ou de colega: a memória pertence a um agente, a um usuário ou a uma máquina, e até a memória guardada no git é feita de anotações do próprio agente; o vault é o registro do projeto — aprovado, revisado, com status — e circula pelo git.

Preciso do Obsidian?

Não. O vault é uma pasta comum de arquivos Markdown. Abra em um editor, navegue no GitHub ou use o Obsidian, se você gostar do grafo e do quadro dele. Sem o plugin, os arquivos continuam igualmente legíveis.

Ele chega a gravar algo sem perguntar?

Não. Todo arquivo novo ou edição é mostrado a você primeiro, com o caminho e o texto completo. Em seguida, o ProjectStore espera Sim, Editar antes de salvar ou Não. Os assistentes que acompanham a conversa apenas sugerem um comando. O único agente que pode gravar, o clerk, roda depois do seu Sim e salva exatamente o que você aprovou.

O que fica se eu o remover?

O seu vault, intacto: é Markdown puro em um repositório git próprio. O vínculo do projeto e os modelos de agentes da equipe também ficam, então uma nova instalação os encontra. O plugin do Codex é registrado para todos os projetos da máquina, por isso removê-lo é um passo à parte. Como remover
