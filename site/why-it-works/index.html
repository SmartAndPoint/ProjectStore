.projectstore / method / 2

The industry invented this long ago.
Agents made it cheap.

ADRs, reviews, a backlog, acceptance criteria, links from goal to code. Mature engineering teams have worked this way for twenty years. ProjectStore invents none of it.

Where each piece comes from

Where each piece comes from

  1. 1969RFCs: decisions written down and numbered, then discussed in the open.
  2. 1992DO-178B: in avionics, every requirement must trace to code and to a test.
  3. 1995Scrum: the work as a backlog, ordered and visible.
  4. 1999XP: user stories, and acceptance criteria that say when one is done.
  5. 2007Kanban for software: a board that shows what is in flight.
  6. 2011ADRs, Michael Nygard: one short file per architectural decision.
  7. nowCoding agents: every step takes minutes. Without the artifacts, every session starts empty.
What the artifacts do

One project, many hands. The same ground for all of them.

An ADR says what was decided and what was rejected. A spec says how it must work. An epic and its stories say what is being built and when each part is done. The board shows what is in flight.

With them, an engineer who joins tomorrow, a reviewer from another team and an agent in a fresh session all start from what the first person knew. That is why teams that build large systems have kept these documents for decades.

The expensive part

The process was always valuable. What was expensive was people running every step of it.

The process works. Its documents are the most valuable thing a company keeps after a project: why the system is built this way, what counted as done, where each feature lives in the code. But when people run it by hand, it is slow. An ADR takes an afternoon to write and a week to get reviewed. Documents fall behind the code. The board stops matching reality. So teams cut corners, and "agile" becomes an excuse to write nothing down.

Where the artifacts are missing, it looks the same with people and with agents: settled questions come back, nobody can say why the code is the way it is, and every newcomer starts by guessing.

Agents are the opposite. Writing an ADR, splitting an epic into stories or checking a diff against criteria takes an agent minutes, not days. What an agent lacks is what people get for free: memory between sessions, context shared with colleagues, the link from a goal to the code. Every new session starts empty and decides again what was already settled.

people's process+agents' speed=ProjectStore

ProjectStore puts the two together. Agent speed makes the old process cheap for the first time. Its documents, kept in files beside the code, give agents what they never had: the project's context, linked up to the goals and down to the code. A second agent that did not write the draft reviews each step, by rule. Speed gets a memory, and memory gets a check.

The links live in the header of each file, and the proof is a line under each acceptance criterion. The agent fills all of it in as it works. The link map shows what each document connects to. The code map shows where each epic's code lives. A new session, a new model or a new colleague starts from this chain, not from nothing.
