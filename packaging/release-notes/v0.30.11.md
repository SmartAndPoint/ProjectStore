# v0.30.11 — test stories, and doctor shows which contracts have only the happy path

This release adds a test story: a story that plans the tests for a spec's contracts, written to a test lead's guide. It also lets a spec mark its edge and failure scenarios, and doctor now shows the contracts whose scenarios show only the happy path.

## Test stories

A story made with the variant flag is a test story:

```
/projectstore:story PS-X "Tests for the stale-index contract" --variant test
```

The command writes `variant: test` into the story's frontmatter and reads a new guide, `story.test`, before the draft. The guide asks the story to name the contracts it covers by citation token, to list the cases that apply to each (boundary values, invalid input, state transitions, failure of a dependency, retry and concurrency, partial failure, upgrade from an older state, rollback), to say which cases it leaves untested and why, and to require a citation on every test it adds. The critic reviews the story against the same guide. In every other way a test story is a story: the same gates, evidence and board. A vault that overrides `guides/story.md` still gives a test story the package `story.test`; to change that one too, run `guide eject story.test --write`.

Only `test` is defined; the command refuses another value. The six story templates carry a commented `# variant: test` line.

One fix comes with it: `--spec SPEC-ID` used to end up in the story's title and file name. The command now removes both flags before it renders the draft.

## Edge and failure marks on scenarios

A scenario's `WHEN` or `GIVEN` item can end with `(edge)` or `(failure)`. `(edge)` is for a case that comes from the input or the state: boundary values, invalid input, a state transition, an upgrade. `(failure)` is for a case where something else fails: a dependency, a retry or a concurrent run, a partial failure, a rollback. A happy-path scenario has no mark.

For each active spec, doctor now reports `contract-happy-path-only` (info): the contracts that have scenarios and none marked. It counts the marks and does not judge them; whether a marked case is real is the critic's question. Doctor also reads a scenario item together with its wrapped lines now, so a long item that wraps is one item.

[`docs/contracts-and-tests.md`](https://github.com/SmartAndPoint/ProjectStore/blob/main/docs/contracts-and-tests.md) shows the marks and a test story.

## Upgrading

Nothing migrates, no state moves, and the agents block stays v5. A spec with scenarios and no marks gets the new info from doctor; adding the marks, or leaving them out, is your choice. Codex's story skill changes, so Codex needs its own upgrade, below.

From npm, from a terminal in your project:

```
npx projectstore@0.30.11 upgrade
```

Codex's registration is per machine:

```
npx projectstore@0.30.11 upgrade --harness codex
```

From the git marketplace, in a Claude Code session: open `/plugin manage` and choose **Update now** on projectstore, then run `/reload-plugins` to load it. Or, from a terminal, then restart Claude Code:

```
claude plugin update projectstore@SmartAndPoint
```
