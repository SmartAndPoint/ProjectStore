# v0.30.22 — edit a story's, an epic's or an initiative's text, on the dashboard and from a terminal

This release has one pull request (#178). A new verb, `edit`, rewrites the sections under an item's title and field table without an agent session, and the dashboard's page uses it: a story, an epic or an initiative opens as its own editor, with marks for what you changed.

```
npx projectstore@0.30.22 dashboard
```

## The dashboard's editor

While the page can write, the text of a story, an epic or an initiative is an editor, as in Obsidian. The title stays above it, and the fields are not part of the editor: an epic's and an initiative's field table stands above the text, a story's fields in the side panel. What you add is green and what you remove is red and struck through, in the place where it stood; the selector beside **Save** compares with where your changes started ("All your changes"), with your last save ("Changes not saved yet"), or turns the marks off.

**Save** (or ⌘S anywhere in the panel) commits your text on the same batch branch as a move, through the core's `edit` verb, and **Publish for review…** sends it as before. If the file changed while you typed (a move from the side panel, another tab, **Get the latest backlog**), the save is refused and a note says so: copy your text, open the document again and put your change into it. Text you have not saved is kept in this browser and comes back after a reload.

An ADR, a spec or a research note still opens read-only: the edit verb writes three kinds. A picture pasted or dropped into the text is not kept yet; the page says so and adds nothing.

**Check the editor** in the ⌘K palette runs twelve checks on the open item, types, pastes and removes text, and puts it back. Nothing is saved.

The editor is CodeMirror 6. Its build is committed in the page's package with the licence texts of every package in it, in `THIRD-PARTY-NOTICES.txt`, so the package grows from about 134 KB to 366 KB packed.

## The `edit` verb

```
npx projectstore edit epics/PS-CORE/stories/story-faster-login.md
```

Bare, it prints the sections under the title and the field table, and their hash. Your text starts at the first `## ` section; the title and the field table are not part of it. With a file and that hash it shows the plan, and with `--write` it writes:

```
npx projectstore edit epics/PS-CORE/stories/story-faster-login.md --from new.md --base 0123456789abcdef --write
```

It writes only when the file's text still has that hash. It refuses a change to a story's Status log or an initiative's Outcome, and a text that checks a criterion or an Expected Result, or rewords one that is checked; it reads those sections in every language a vault can use. An unchecked one you may rewrite, and a checked one you may uncheck or remove. It marks the file not reviewed (`written_by_verb: "edit <time>"`, `review_status: pending`, `reviewed_at: null`), as `create` does, and leaves `updated` and the "Last updated" line alone, so the age of a story does not reset. Then it refreshes the derived views, as the other writing verbs do. It works on a story, an epic or an initiative.

What the mark changes, as after `create`:

- doctor lists each marked file as `verb-mark` (info) until `/projectstore:review` reads it or `reviewed` clears it;
- a story's plan gate reviews the marked files first: the story itself, its epic and the epic's initiative, so editing an epic means the next plan of any of its stories reads that epic first.

## What it runs, writes and sends

- Opening a story, an epic or an initiative to edit, saving it, or getting the latest runs `git merge-base`, `git cat-file -e` and `git show` in the page's own clone, to find where your changes started. They read the clone and write nothing.
- **Save** runs ProjectStore's `edit` in the clone through the same Node, as a move runs `move`. The text you save goes to a file of its own in your system's temporary folder, readable by you alone, and is removed when the verb ends.
- The page keeps a text you have not saved in this browser's storage for the page's address, under the file's path in the vault, until you save it or put it back.
- The server takes a request body up to 16 MiB (it was 64 KiB), so a long text can be saved.
- Nothing new is sent: Save commits in the clone, and only **Publish for review…** pushes, as before.

## Upgrading

Nothing migrates. What changes when you upgrade:

- a story, an epic or an initiative written by `edit` carries `written_by_verb`, `review_status: pending` and `reviewed_at: null` until `/projectstore:review` reads it, as after `create`;
- stop a running dashboard and start it again: an older server keeps serving its own older page, which has no editor. A second `dashboard` started while the old one runs takes the next free port, and the old tab stays old. In a checkout updated under a running server, the text opens read-only and says "The server is older than this page";
- the dashboard's clone in `.projectstore/state/dashboard/` stays as it is, with its open batch and kept branches; a save goes on the same batch branch as a move;
- an npm copy fetches the dashboard's package for 0.30.22 on its first `dashboard` run, into `dashboard/0.30.22/` beside the old version's folder, which stays.

The commands, agents and hooks are the same, but the CLI gains a verb, so an installed copy needs the upgrade to run it.

From npm, from a terminal in your project:

```
npx projectstore@0.30.22 upgrade
```

Codex's registration is per machine:

```
npx projectstore@0.30.22 upgrade --harness codex
```

From the git marketplace, in a Claude Code session: open `/plugin manage` and choose **Update now** on projectstore, then run `/reload-plugins` to load it. Or, from a terminal, then restart Claude Code:

```
claude plugin update projectstore@SmartAndPoint
```

The git marketplace serves `main`, so a copy installed, or updated from an older number, since #178 merged may already have the verb and the editor under the number 0.30.21; a copy that was already at 0.30.21 gets them with this release's number.

The agents block stays v5, and the MCP tools are the same nine.

## Not seen live yet, and known gaps

- The editor was checked in a Chromium only. The launcher opens your default browser, which may be Safari or Firefox.
- A paste from the system clipboard, a drag with a real mouse and an input method for another script were not tried.
- An upgrade over an open 0.30.21 batch, and a save published as a pull request on GitHub, were not tried; the checks before the tag used a fresh clone and a local origin with no `gh`.
- On Windows the page still reads only, so there is no editor there.
- `edit` writes a file with Windows line ends (CRLF) back with plain line ends (LF).
- An unsaved text is kept under the file's path in the vault for the page's address. Two vaults with the same path, opened on the same port at different times, see each other's unsaved text. When the two files hold different text, the page shows it with the note that the file changed and does not save it. When they hold the same text (a copy of one vault), it comes back as your own unsaved text and Save writes it. "Throw it away" clears it either way.
- Pictures and PDFs in a text, a comparison with any earlier save, and an editor for ADRs, specs and research notes are three stories still to come.
