# v0.29.4 — Setup installs ProjectStore for every agent in one plan

This release adds `setup`: one command that asks a few questions, shows one plan, and installs ProjectStore for every coding agent the project uses, with its vault. Every command a run prints can now be copied as it stands, and a closed story no longer stays on the band.

## Setup

From a terminal in your project:

```
npx projectstore@0.29.4 setup
```

At a terminal it asks:
- which folder is the project;
- which agents to set up: Claude Code, Codex or both, pre-ticked where they are used or ready;
- where the vault lives. An existing folder is bound; a missing or empty one is created, with its own git repository and the layout's folders;
- whether to show ProjectStore in the status line;
- when the checkout already loads ProjectStore from the git marketplace, whether to switch it to the npm install (the default) or keep the git marketplace.

Then it prints one plan, with every file it writes and every host command, and asks once. Ctrl+C writes nothing. Restart the agent afterwards; Codex asks you to approve the ProjectStore hooks.

- `--dry-run` shows the questions and the plan, and writes or fetches nothing.
- Without a terminal nothing is asked. `--harness <id>` names an agent and is the confirmation, `--vault <path>` names the vault, and `--channel npm` or `--channel git` answers the git-marketplace question.
- Inside a Claude Code or Codex session, setup writes the project's own files and leaves that agent's registration for a terminal. DONE prints the command to run there.

The bind command no longer asks about auto-update. Doctor still names the setting when it is off.

## Commands you can copy

Every command a run prints now stands alone on its own line, after a lead that says where to run it. That covers doctor's findings, the startup line, the welcome, DONE's tip and the refusals. The command names no project path and no per-agent package. It runs the core package with `--harness <id>`, or the installed copy's own bin, or it is the command to type in the session. When the startup line has several parts, each gets a line of its own.

A refusal with lines of its own is now printed whole. Before, the plan cut the start of every further line, so `--harness claude-code` read `laude-code`.

## A closed story leaves the band and the status line

A story closed through the story command, or by any write, stayed on the band and the 📚 line as "in progress" until the session ended. Now:
- the band reads the story's title and status from its file, and shows no row for a done, closed or parked story;
- the session's pointer is updated after a write instead of before it, and the close runs a new `session refresh` verb;
- a long title is cut with `…`, never the status;
- a session that starts on a stale pointer corrects it.

## The old layout gets one more release

A project still on the pre-0.28 layout keeps working through 0.30. The fallback closes at 0.31. Move the project before then, with the command the startup line names or with setup.

## Upgrading

Claude Code from npm, once per project, from a terminal in it:

```
npx projectstore@0.29.4 upgrade --harness claude-code
```

The 0.29.3 form still works too:

```
npx projectstore-claude@0.29.4 upgrade --project "$PWD"
```

Codex, once per machine, from a terminal outside any Codex session:

```
npx projectstore@0.29.4 upgrade --harness codex
```

Claude Code from the git marketplace:

```
/plugin update
```

Then restart the agent.

**What you may see afterwards:**
- Doctor reports the status-line launcher as `stale: source changed`. The line keeps rendering. The npm upgrade above re-stamps it. On the git marketplace, re-stamp it in a session:

  ```
  /projectstore:doctor --fix
  ```

- A project bound before setup needs nothing. Running setup at a terminal is optional: it asks only about the status line, and about the channel when a git-marketplace copy is enabled.
- The README on npm's page for 0.29.4 still shows the per-agent packages. 0.30.0 updates the documents.

Codex stays **experimental**, as [docs/harnesses.md](https://github.com/SmartAndPoint/ProjectStore/blob/main/docs/harnesses.md) defines it.
