# v0.30.8 — the plugin directory's policy holds fixed or kept with a reason, and the front page in eight languages

This release answers the policy holds that Anthropic's plugin directory raised on 0.30.7. Nothing ProjectStore does has changed: the fixes change how the code is written, not what it does, and the holds it keeps now carry their reasons. It is meant to be the version the directory listing comes from.

## The directory's policy holds, fixed or kept with a reason

The developer portal validated 0.30.7's `directory` branch, the tree Anthropic's directory scans: it passed, with nine policy holds, each of which sends the version to a reviewer. The portal does not publish its rules, so each fix answers what its report showed, and the portal's next Validate is the proof.

- **The band above the prompt.** The band's hook on agent starts (`agent.spawn`) read to the scan as one that might answer a permission request. The report pointed at the hook; what the code could change was that the names of its event and of `next` were also bound elsewhere in `hooks/band.tsx`. Those bindings are renamed, so the hook visibly passes its own event on. The heartbeat write now spells its path out as text, `.projectstore/state/sessions/.band-<session id>.json`, so the scan can read where the band writes. It is the same file with the same content, and the band behaves as before.
- **No credential-shaped name beside a URL.** The scan reads a file that holds a URL and a word such as `key` or `token` as one that may send a credential. The comments in `scripts/term.mjs` and `scripts/convergence.mjs` no longer hold URLs, and npm's default registry address moves into `scripts/fetch-shell.mjs` beside the public registry's, so one file spells it. The README's and `llms-full.txt`'s MCP line is now `npx projectstore mcp --project .`, without a shell variable.
- **"vault read".** The review command's prompt said `<vault README excerpt>`, which the scan read as a secrets store's `vault read`. It now says `<the vault's README excerpt>`, in Claude Code and in Codex. The status line command and a comment in the session hook say "no read of the vault".
- **Kept, with a reason.** These findings stay, each with its reason written down. `hooks/band.tsx` holds one URL, the SVG namespace of the progress bar's drawing, which is never fetched; its `token`, `key` and `pin` are the hint's command, the band's own state and the pinned epic's id. `scripts/fetch-shell.mjs` holds npm's public registry, read with one request for the newest release that sends no credential; its `token` is advice on where npm keeps the user's own registry token, which ProjectStore never reads. When setup sets up Codex it runs npm with your environment, so npm reads its own registry, proxy and login settings and fetches the Codex package from the registry your npm is set to, as npm always does; ProjectStore reads none of them. The PreToolUse hook decides nothing: its output is empty or a message, never a permission decision, and a test holds it to that. The listing's icon, `docs/images/icon.png`, is named only by the manifest's `icon` field and nothing runs it; the portal holds an image it did not read as code, once per version.

## The README says what the band writes and watches

The README's section on what ProjectStore runs and writes now names the band's heartbeat file, `.band-<session id>.json` under `.projectstore/state/sessions/`. It also says that the band watches agent starts (`agent.spawn`), each agent's requests and tool calls, and each turn's end, only to show a ProjectStore agent's row; that it passes each of these on unchanged; and that it changes no agent, permission or setting.

## The front page in eight languages

https://projectstore.dev/ is now in all eight of the site's languages: English, German, Spanish, French, Portuguese, Russian, Ukrainian and Chinese. Until now the six other addresses opened the English page. The comparison now covers agent memory beside a prompt in a chat, SDD and PDD, and adds a rating of what holds up in a long project, a choice tree and a ladder. The site's default look is now dark (midnight); a system set to a light theme gets paper, a light beige. Links that leave the site open in a new tab.

## For contributors: four more directory-guard rows

`packaging/directory-guard.mjs` checks the patterns behind the holds, by file and line, in CI and in `npm run release:check`: a band hook whose event or `next` name is used elsewhere, a band write whose path is not fixed text, a credential-shaped name beside a URL, and "vault read" in a command, skill, agent or hook file. A file kept on purpose is named with its reason, and a kept file that a row no longer matches fails, so the list cannot outlive its reasons. A test holds the band's heartbeat path to the layout's folder and file name.

## Upgrading

Nothing to migrate, and no state moves. The agents block stays v5.

From npm, from a terminal in your project:

```
npx projectstore@0.30.8 upgrade
```

Codex's registration is per machine:

```
npx projectstore@0.30.8 upgrade --harness codex
```

From the git marketplace, in a Claude Code session: open `/plugin manage` and choose **Update now** on projectstore, then run `/reload-plugins` to load it. Or, from a terminal, then restart Claude Code:

```
claude plugin update projectstore@SmartAndPoint
```
