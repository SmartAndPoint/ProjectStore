# v0.30.7 — configure reads no credential, and Claude Code's model list is its four aliases

This release removes the one place where ProjectStore read a credential from your environment. It is meant to be the version ProjectStore's first submission to Anthropic's plugin directory comes from.

## The model menu no longer reads ANTHROPIC_API_KEY

Until now, when `ANTHROPIC_API_KEY` was set, `configure` sent it to Anthropic's model list (`api.anthropic.com`, or `ANTHROPIC_BASE_URL` when that was set) to show which model each Claude Code alias follows. Anthropic's directory holds for review every plugin version that reads a credential already set in your environment and sends it to a server, and ProjectStore should not need your key to show a menu.

From 0.30.7, ProjectStore reads no credential from your environment. Claude Code's model list is its four aliases, `fable`, `opus`, `sonnet` and `haiku`, each with its own description, whether the key is set or not. The menu asks nothing for Claude Code: its footer says "aliases only", and "refresh the list" says there is nothing to ask. Claude Code itself still reads its own variables as before, and each alias still starts the newest model of its line.

A model list that 0.30.2 to 0.30.6 kept from Anthropic's API in `~/.cache/projectstore/models/claude-code.json` (under `$XDG_CACHE_HOME/projectstore/` when that is set) is no longer shown. It is not deleted, and it holds no key: model names, labels and families, and the date it was read. Delete it by hand if you like.

Codex's model list is unchanged: Codex's own catalog, refreshed by `codex debug models` with your Codex login. Codex's hook commands are unchanged too.

## What ProjectStore sends: two requests

The README, the privacy page and `llms.txt` now say two requests, not three: one to the npm registry, from setup, install and upgrade (off with `PROJECTSTORE_NO_UPDATE_CHECK=1`), and one for the `projectstore-codex` package, fetched only when setup, install or upgrade sets up Codex. Each one comes from a command you run, never from a hook. A new check fails the build when a shipped file names a credential variable, so a later change cannot bring the read back unnoticed. The privacy page is at https://projectstore.dev/privacy/.

## A model off Claude Code's aliases is named as that

An agent whose model in `.projectstore/harness/claude-code.json` is not one of the aliases now reads "Not one of Claude Code's aliases. It is kept as it is." in the menu. Claude Code's spawn takes only the aliases, as before, so pick one where the menu marks this.

## A new front page

https://projectstore.dev/ now says what ProjectStore is in plain words, walks a beginner through setup, and plays the loop in a player, in English and Russian. The front page's German, Spanish, French, Portuguese, Ukrainian and Chinese addresses now open the English page; the method pages keep all eight languages. The site's default look is now light.

## For contributors: release checks work under npm 12

npm 12 answers `npm pack --json` with an object keyed by the package's name instead of an array. The version guard, the packlist and the shells' build read both forms now, so `npm run release:check` passes on npm 12.

## Upgrading

Nothing to migrate. The agents block stays v5.

From npm, from a terminal in your project:

```
npx projectstore@0.30.7 upgrade
```

Codex's registration is per machine:

```
npx projectstore@0.30.7 upgrade --harness codex
```

From the git marketplace, in a Claude Code session: open `/plugin manage` and choose **Update now** on projectstore, then run `/reload-plugins` to load it. Or, from a terminal, then restart Claude Code:

```
claude plugin update projectstore@SmartAndPoint
```
