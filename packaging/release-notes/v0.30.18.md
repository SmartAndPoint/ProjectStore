# v0.30.18 — a session checks its vault files before a commit, doctor checks the flow, and an epic closes itself

This release has three changes. Before a vault commit, a session can learn which files hold edits it did not make. Doctor checks the flow against the vault's `flow` policy. And an epic becomes done by itself when its stories are done and its expected results are checked.

## A session checks its vault files before a commit

ProjectStore never commits. Each session commits its vault work itself, a whole file at a time. When two sessions edit one file, the first to commit takes the other's uncommitted edits too. This happened twice in this project's own vault in one day.

A session now keeps a record of its own vault writes, and a new check reads it:

```
/projectstore:precommit
```

From a terminal, name the session: `npx projectstore@0.30.18 session check --session <session id> [<path>…]`. Without it every changed file reads as unattributed.

**The record.** It lives in `.projectstore/state/sessions/<session-id>.writes/`, on this machine only, and is never committed. Three kinds of write go into it:

- the agent's Edit, Write, MultiEdit and NotebookEdit tool calls on vault files, through the tool-call hook: the file before and after each call;
- the plugin's own vault writes: `move`, the epic-row update, `configure` and `guide eject`;
- the whole-file copy the clerk makes at a story close. The close flow brackets it with `session snapshot --for <scratch>` before the clerk starts and `session record --from <scratch>` after.

Reconcile, scaffold and bind are not recorded, and neither is a write made through the shell (`sed -i`, `cp`, `mv`, `rm`) outside the close bracket. Writes made before the upgrade are not in the record either, so a file the session edited then reads as not its own.

Limits:

- A file over 512 KiB keeps its hashes but not its content, and so does everything once a session has stored 64 MiB.
- The record is deleted at a session start once it has been idle for 24 hours. A session's own record is kept when that session starts again with the same id.

**The check.** It lists each changed vault file and says whether it is the session's own: whether it can be reached from what HEAD holds through the session's recorded writes alone. A file that is not the session's own does one of two things:

- it names a live session that claims the path, with the lines that are not yours;
- otherwise it is "unattributed".

The check also covers:

- **Staged paths.** They are judged by what the index holds.
- **Created, deleted and untracked files.** These are listed too.
- **Derived views** (`kanban.md`, `graph.md`, `code-map.md`, folder indexes). A view is judged by the files that feed it. A folder index's own prose is judged by the replay.
- **Line endings.** HEAD and index content is read in two forms, raw and with git's filters (`cat-file --filters`, which runs the repository's configured filters). This keeps `core.autocrlf` from making your own files look foreign. The one case it misses: under `core.autocrlf=input`, a file kept with CRLF on disk reads as foreign.

It exits 0 when every listed file is yours, 1 when one is not, during an open merge, or when git could not be read, and 2 for a path outside the vault. Its last line says what to do: commit your own files by naming their paths, leave the others out, and tell the person. During an open merge, or when git could not be read, it says not to commit.

**Git is read only.** The check runs `git status`, `git cat-file` and `git rev-parse` in the vault's repository, with `GIT_OPTIONAL_LOCKS=0`, so the index is not rewritten. ProjectStore still never commits, pushes, pulls or fetches.

**Where the stop is said:**

- the check's last line;
- a third paragraph in the session-start rules;
- the commit hints in the adr, review and story commands.

**Claude Code only for now.** The record and the rules paragraph need a session id from the host. Claude Code declares one. Codex does not yet, so on Codex nothing is recorded, the rules carry no third paragraph, and the check says the host gives no session id and to ask the person.

**Not seen live yet:**

- whether every Claude Code hook call carries the id the record is keyed by;
- whether a resumed session keeps its id;
- what a subagent's calls carry.

When one of these is missing, the check fails closed: files read as not yours. They are recorded after the release.

## Doctor checks the flow

`doctor --vault` has a new flow group that checks the vault against its `flow` policy (0.30.16 stored the policy, and nothing read it until now):

- WIP per person (`flow.wip.full` or `flow.wip.part` for a person listed in `flow.people` with that time, or the person's own `flow.people[<name>].wip`);
- age in status (`flow.age_days.review`, `flow.age_days.todo`);
- idle work and idle people (`flow.age_days.in_progress_idle`, `flow.idle_days`);
- intake against close (`flow.window_weeks`);
- ToDo against capacity (`flow.capacity_weeks`, together with `flow.window_weeks`).

Each check runs only when its key is set. Findings are warn or info, never issue, so the flow never changes doctor's exit code. The flow group is not part of the `--startup` subset. A vault with no `flow` block gets one info, `flow-policy-unset`.

The idle checks read activity from one `git log` per run, in the project's repository (not the vault's), over all local and remote branches plus HEAD, with no merges, and only when `flow.age_days.in_progress_idle` or `flow.idle_days` is set. It reads author and committer names, times and paths, and never an email address. The README's "What it runs" row says so.

Stories with no trusted `status_changed_at` are aged from `updated`, and a `status-unstamped` info counts them.

## An epic closes itself

The story close now runs the epic rule. An epic that is not itself done or set aside becomes done when all four hold:

- at least one of its stories is done;
- every other story is done or set aside (superseded, deferred or parked);
- its Stories table has no open row without a story file;
- every Expected Result is checked.

The close preview lists every epic that would move, not only this story's. A new step writes the move, regenerates kanban, code-map, graph and indexes, and runs `doctor --vault` when something moved. The rule rewrites the epic header's Updated row with the status. It can be run on its own, to see what would move:

```
node <plugin root>/scripts/epic-rule.mjs <story> --assume-done
```

To apply, run it with `--write` in place of `--assume-done`, then `reconcile --write --only kanban,codemap,graph,indexes`: the script runs no reconcile.

Doctor's `epic-status` check no longer counts superseded, deferred or parked stories as open. A done epic with set-aside stories therefore loses that warning.

The rule's writes go through the session's write record, so the pre-commit check counts a moved epic as the session's own write.

## Upgrading

Nothing migrates and no state moves. The agents block stays v5.

What changes after the upgrade:

- The first story close may move older epics that already pass the rule, and its preview lists them first.
- A vault with no `flow` block gets one `flow-policy-unset` info.

Codex's skills change (a new `projectstore-precommit` skill, plus story, adr and review), so Codex needs its own upgrade, below.

From npm, from a terminal in your project:

```
npx projectstore@0.30.18 upgrade
```

Codex's registration is per machine:

```
npx projectstore@0.30.18 upgrade --harness codex
```

From the git marketplace, in a Claude Code session: open `/plugin manage` and choose **Update now** on projectstore, then run `/reload-plugins` to load it. Or, from a terminal, then restart Claude Code:

```
claude plugin update projectstore@SmartAndPoint
```
