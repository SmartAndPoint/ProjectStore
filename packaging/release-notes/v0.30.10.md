# v0.30.10 — one authoring guide per artifact kind, and a story may say why it needs no spec

This release gives every artifact kind one authoring guide. The session that writes an ADR, spec, epic or story reads it before the draft, and the critic checks the same list after. A project can change the guide in its own vault. The release also lets a story declare that it needs no spec, with a reason, and lets the lifecycle gates work under any spec policy.

## Authoring guides: the author and the critic read one list

Before, the checklist for each kind lived only in `scaffold/checklists.json`. Only `/projectstore:review` read it, after the draft was written, and a critic started directly from the agents block did not see it at all. That file is gone. Each kind now has a guide in `scaffold/guides/<kind>.md`, with five sections: `## Lens` (whose eye this kind needs), `## Must` (the checklist), `## Common mistakes`, `## Do not write` and `## Length`. All 45 checklist items moved under `## Must` as they were. The guides for adr, spec, epic and story also have the other four sections; research, concept, meeting and runbook have only `## Must` for now.

Who reads a guide:

- Each authoring command (`/projectstore:adr`, `spec`, `epic`, `story`, `research`, `concept`, `meeting`, `runbook`) reads its kind's guide before it renders the draft.
- The critic reads the guide of the artifact it reviews, takes `## Common mistakes` into its first list of likely problems, and reports each failed `## Must` item by its text. For a kind with no guide it says the review ran without a kind checklist. `/projectstore:review` passes the same items.
- The peer-reviewer skill reads `default_review` from the guide.

A project can override a guide in its vault, as `<vault>/guides/<kind>.md`. The file replaces the package guide whole. To start from the package default:

```
npx projectstore guide eject spec --write
```

Eject only creates the file: it asks first at a terminal, and it never replaces a file that is there. To read a guide:

```
npx projectstore guide spec --section Must
```

`--source package` reads the package default behind an override. Doctor has three new checks for the vault's `guides/` folder: `guide-shape` (an override that does not parse, so readers use the package default), `guide-unknown` (a guide for a kind the layout does not have) and `guide-stale` (an override made from an older package default). Files in `guides/` are not artifacts: they make no name collision, no link target, no stale view and no search hit.

The MCP server has a ninth tool, `guide`, with the same result as the verb, so a harness that reaches ProjectStore only through MCP gets the guide too. The whole `tools/list` is now about 1,400 tokens, under the 3,000-token budget the MCP ADR sets.

## A story can say it needs no spec, with a reason

At the plan gate a story can now declare `no_spec: "<reason>"`. Under `spec_policy: required`, doctor accepts the reason instead of a covering spec. Under any policy, doctor reports an empty reason, or `no_spec` beside `specs:`, as an issue. It warns when a `no_spec` story touches three or more source files. Once any story opts out, doctor shows an info with the count of opt-outs against covered stories among recent code stories, and it warns when opt-outs outnumber covered ones (with at least five stories in the window). The reviewer applies the same size rule at close.

## The lifecycle gates get their own date

`configure` now stamps `gates_since` in the vault's `.projectstore.json` when `lifecycle_gates` turns on. The lifecycle checks count from `spec_policy_since`, else from `gates_since`, so they work under `spec_policy: optional` too. Stories closed before the date are not checked. When the gates are on and have no date, doctor suggests the stamp. Evidence checks now read a checklist item together with its wrapped lines, so `— evidence:` on a second line counts.

An accepted ADR whose `review_by` date has passed gets an info from doctor.

## A dry run of `spec_policy: required`

```
npx projectstore doctor --vault --policy required
```

It reports the vault as if `spec_policy: required` were set, from now or from the date you give (`required@2026-11-01`). It writes nothing. The MCP `doctor` tool takes the same `policy` parameter.

## Upgrading

Nothing migrates on any channel, no state moves, and the agents block stays v5. Codex's skills change (the authoring commands, review, doctor and the agents now read the guide), so Codex needs its own upgrade, below. A session that is open during the update gets the ninth MCP tool after a restart or `/reload-plugins`. No vault gets a `guides/` folder until you run `guide eject --write`. One optional step for a vault that already has `lifecycle_gates: on`: doctor will suggest stamping `gates_since`, which you do with the command it prints.

From npm, from a terminal in your project:

```
npx projectstore@0.30.10 upgrade
```

Codex's registration is per machine:

```
npx projectstore@0.30.10 upgrade --harness codex
```

From the git marketplace, in a Claude Code session: open `/plugin manage` and choose **Update now** on projectstore, then run `/reload-plugins` to load it. Or, from a terminal, then restart Claude Code:

```
claude plugin update projectstore@SmartAndPoint
```
