# v0.30.15 — a spec's amendments are marked, checked and drawn

This release gives a change to an active spec's contract one marked form. Doctor checks it, and the graph shows which stories changed a spec. Until now such a change was a prose note under the contract. No script read the note, so doctor and the planner kept reading the old text.

## The marker

A change to a contract is a blockquote right after that contract. Its first paragraph is:

```
> amended 2026-11-10 by EPIC-ID/story-id: MODIFIED — why it changed
```

The kind is `ADDED`, `MODIFIED` or `REMOVED`.

- With `MODIFIED`, the contract's body holds the text in force, and the block quotes what it replaced.
- With `REMOVED`, the contract keeps its number and heading, its body becomes `Removed, see below.`, and the block quotes the removed text. A removed step inside a contract stays the same way, so the steps after it keep their numbers and a citation such as `[example#4/3]` still points at the same step.
- With `ADDED`, a new contract takes the next free number. A number is never reused.

The story a marker names and the spec list each other, in `specs:` and `stories:`. The first marker under a contract folds the older prose blocks under it into the body and quotes them inside its own block. Other old blocks stay as they are and are not parsed.

The tokens `amended`, `by`, the three kinds and `Removed, see below.` are English in every locale. A ref whose epic part is `example` is documentation and is skipped.

## What checks it

Doctor reports:

- `amendment-story` (issue): the ref names no story, or more than one;
- `amendment-link` (warn): neither the story nor the spec lists the other;
- `amendment-date` (warn): a bad date, a date before the spec's own, after tomorrow, or before the previous marker under the same contract;
- `amendment-form` (warn): something that looks like a marker, in any case, but does not parse. A marker after `REMOVED` or before the first contract also counts.

A test that cites a removed contract or step gets `citation-removed` instead of `citation-unknown`, with the marker's reason. Evidence in a closed story that cites one is skipped, so a later removal does not make an old story warn. The contract count, the happy-path check and the scenario checks leave removed contracts out.

A blockquote under a contract whose first line reads `Amended <one word> by …`, in any case, now gets `amendment-form`. The italic `> *Amended …*` notes are not touched.

## What draws it

`graph.md` gets an `amends` edge from the story to the spec, one per pair. `lineage` and `graph lineage --kind amends` walk it. Regenerate `graph.md` after the upgrade, with `/projectstore:graph` (or `$projectstore-graph` in Codex). In a vault with at least one valid marker, doctor's graph check is an issue in both directions while two versions share the vault: 0.30.15 flags a `graph.md` written by an older copy, and an older copy flags one written by 0.30.15.

## Texts

- The spec guide is at version 2. It has four new Must items for what doctor cannot see: no new old-form block, no reused number, a body rewritten under `MODIFIED`, a fold that kept its meaning. Blocks under contracts do not count toward its length.
- The spec template, in six locales, shows the marker in a comment.
- The story command's plan step amends a covering spec with a marker. The planner names the contracts a story will amend, and the reviewer checks that a story's spec edits carry markers.
- The graph command names the `amends` kind, and the doctor command lists the new findings.
- `docs/contracts-and-tests.md` has a section on amending a contract.

## Upgrading

Nothing migrates and no state moves. The agents block stays v5. Codex's graph, planner, reviewer and story skills change, so Codex needs its own upgrade, below.

From npm, from a terminal in your project:

```
npx projectstore@0.30.15 upgrade
```

Codex's registration is per machine:

```
npx projectstore@0.30.15 upgrade --harness codex
```

From the git marketplace, in a Claude Code session: open `/plugin manage` and choose **Update now** on projectstore, then run `/reload-plugins` to load it. Or, from a terminal, then restart Claude Code:

```
claude plugin update projectstore@SmartAndPoint
```
