# v0.30.23 — new items, pictures, earlier saves and Reports on the dashboard, and the editor for an open ADR, spec or research note

This release has seven pull requests (#180, #181, #183, #184, #185, #186, #187). The dashboard can now make an initiative, an epic or a story, keep a picture pasted into a text, compare a text with any earlier save, and show a Reports page. The `edit` verb keeps pictures and PDFs, and takes a proposed ADR, a draft spec and a draft research note too.

```
npx projectstore@0.30.23 dashboard
```

## New on the backlog tree

While the page can write, **New** makes an initiative, an epic or a story through the core's `create`. It is in the tree's toolbar (New initiative, New epic), on each initiative's row and on "No initiative" (New epic), and on each epic's row (New story); the ⌘K palette has the same lines. A done epic, and a rejected or deferred initiative, get no New. As with a move, **Preview** shows what `create` will make and where, and the click is the approval. The new item is one commit on the batch branch, marked not reviewed, and it opens in the editor so you can write its text.

Two people who each add a story to the same epic both add a row at the end of its Stories table, so the second pull request has a conflict in `epic.md`. Merge the first, then resolve the second by keeping both rows.

## Pictures and PDFs in a text

A PNG, JPEG, GIF, WebP or PDF up to 5 MiB, pasted or dropped into the editor, goes into the text as a link to `attachments/<16 hex digits>.<type>`, named by its content. **Save** sends it with the text, and the commit holds the text, the files it links and one line `attachments/** -text` added to the end of the vault's `.gitattributes`. One Save is one request of at most 16 MiB, and pictures travel in it a third larger than they are, so the pictures of one Save add up to about 12 MiB. The page knows a pasted picture only until a reload: after one, it lists the pictures to paste again. A table copied from a spreadsheet stays text. If the vault's git ignores the attachments folder, nothing is committed, and the page names the rule.

A picture linked by a bare file name (`![](shot.png)`, `![[shot.png]]`) is now read from beside the note, as Obsidian reads it, and no longer from `attachments/`. A vault whose pictures sit in `attachments/` and are linked by bare names shows them broken on the page; link them by their path, such as `../../attachments/shot.png`.

From a terminal, the same goes through `edit --attach <file>`, once for each file the text links:

```
npx projectstore edit epics/PS-CORE/stories/story-faster-login.md --from new.md --base 0123456789abcdef --attach shot.png --write
```

It checks every file before it writes anything (its type from its first bytes, its size, a link to it in the text), writes the files first and the text last, and removes its own files again if the text is refused. Every `edit`, with pictures or without, also refuses a text that links a kept name by a wikilink, or links a kept file that is not there. The engineering layout gains `attachments.path`; a layout without it works as before. In the graph a link to a kept file is an edge of a new kind, `attachment`. Doctor has four new findings on files named as `edit` names them, from their names and sizes, never their bytes, and one `git check-ignore` in the vault: `attachment-orphan` (info: no file links to it), `attachment-over-limit` (warn: over 5 MiB), `attachment-type` (warn: not one of the five types) and `attachment-ignored` (warn: the vault's git ignores it). `--fix` changes none of them. A vault that keeps pictures in Git LFS is not covered.

## The editor compares with any earlier save

The selector beside **Save** also lists the file's earlier saves in the page's clone, newest first, at most 30, each with its time, its author and its subject. Pick one, and the marks show what changed since then. The choice holds while the item is open, after a Save too; after a reload or another item you get your usual choice back.

## An open ADR, spec or research note opens as its editor

`edit`, and the page's editor, now take an ADR while it is proposed and a spec or a research note while it is draft, with the same checks and the same not-reviewed mark as a story. A checked item of a spec's Acceptance is guarded as a story's checked criterion is. An accepted ADR, or an active spec, is refused with the status it has and how such a file changes; a superseded, rejected or deprecated one says it is closed. On the page those open read-only with that reason, and a text you had not saved for one of them can still be copied or discarded.

## Reports

A new page, **Reports**, reads the vault with the core's own flow counts: what stands still (stories long in ToDo, Review, In Progress, epics without movement), who holds what against their WIP limit, and the flow week by week (stories created and closed, the columns at each week's end, the median cycle time). A number the page counts itself, not the core, is marked "this page's own". A vault with no `flow` block in its `.projectstore.json` gets the numbers with no verdict, and the page shows the `configure` command that sets one. Its address holds the day, the weeks and the filters (epic, initiative, assignee, priority), so a bookmark keeps the report.

**The board against the code** joins the stories with the project's pull requests, through the same reading as a story's Code block, and lists up to four kinds of mismatch. Each says what it counted, and says it may be incomplete when the list of pull requests or the branch is not known in full. Opening Reports asks for that list at once.

## Unsaved text, kept per project

The editor's unsaved text is now kept under the project, the vault and the file together, not the file's path alone, so two projects opened one after another on the same address no longer see each other's text. A text left unsaved on a 0.30.22 page is not read by 0.30.23. Copy it out of the 0.30.22 page before you upgrade. The old entry is left in the browser, so if you have already upgraded, start the old page on the same address, open the document and copy the text:

```
npx projectstore@0.30.22 dashboard
```

## What it runs, writes and sends

- **New** runs the core's `create` in the page's clone through the same Node, as a move runs `move`.
- **Reports** counts without starting a process. **The board against the code** uses the same `gh pr list` of up to 1000 pull requests as a story's Code block, kept for 10 minutes, and runs it when Reports opens; the descriptions stay in the page's server.
- The earlier saves are one `git log` of that file in the page's clone; a chosen save is read with `git cat-file -e` and `git show` there.
- A save with pictures writes them, with the text, to files readable by you alone in a folder of its own in your system's temporary folder, removed when the verb ends. The server checks each one with the core's own attachment module before any process; the page loads that module at `/attachment.js` and keeps no copy. When git leaves a kept file out of the commit, `git check-ignore -v` in the clone names the rule.
- In the vault: `attachments/` with the kept files, and the line in `.gitattributes`, both only from a save or `edit --attach --write` that links them.
- Nothing new is sent: a save or a New commits in the clone, and only **Publish for review…** pushes, as before.

## Upgrading

Nothing migrates. What changes when you upgrade:

- stop a running dashboard and start it again: an older server keeps serving its own older page;
- a text you had not saved on a 0.30.22 page is not read by 0.30.23 (above);
- a picture linked by a bare name is read from beside the note (above);
- a file written by `create`, by `edit`, or by a save on the page carries `written_by_verb`, `review_status: pending` and `reviewed_at: null` until `/projectstore:review` reads it;
- the dashboard's clone in `.projectstore/state/dashboard/` is used as it is, with its kept branches;
- an npm copy fetches the dashboard's package for 0.30.23 on its first `dashboard` run, into `dashboard/0.30.23/` beside the old version's folder, which stays;
- run one version on every machine that writes the vault: an older copy that rebuilds `graph.md` lists a link to a kept file as out of scope, not as an `attachment` edge, and its doctor has no `attachment-*` findings.

The commands, agents and hooks are the same; `doctor` and `graph` describe the new findings and the new edge. An installed copy needs the upgrade for `edit --attach`, for the new kinds of `edit`, and for the new doctor findings.

From npm, from a terminal in your project:

```
npx projectstore@0.30.23 upgrade
```

Codex's registration is per machine:

```
npx projectstore@0.30.23 upgrade --harness codex
```

From the git marketplace, in a Claude Code session: open `/plugin manage` and choose **Update now** on projectstore, then run `/reload-plugins` to load it. Or, from a terminal, then restart Claude Code:

```
claude plugin update projectstore@SmartAndPoint
```

The marketplace serves the main branch, but the plugin's version is pinned, so a copy installed or updated since #180 merged may already have some of these changes under the number 0.30.22, and a copy that was already at 0.30.22 gets them only with 0.30.23.

## Not seen live

- The page is checked in Chromium only. Safari, Firefox, a picture pasted from the system clipboard, a drag with a real mouse and an input method are not tried.
- On Windows the page still reads only: no New, no editor, no pictures, and **The board against the code** is not read there. `edit --attach` from a terminal is not tried on Windows.
- A pull request opened on GitHub by Send, with pictures in it, is not tried; Send to a bare local origin is.
- **The board against the code** is checked in tests with a stand-in for `gh`, not against a real repository.
- An upgrade over an open 0.30.22 batch is not tried, and neither is the old page started again to copy a text left unsaved.
