# v0.30.2 — Configure opens a settings menu with each harness's own models

At a terminal, configure is now one settings menu, and the models it offers come from each harness itself.

## The settings menu

From a terminal in your project:

```
npx projectstore@0.30.2 configure
```

It works like a monitor's on-screen menu:
- ↑ and ↓ move, → opens a group or a setting in a frame beside it, space chooses, and ← goes back;
- under the frames, a few lines say what the row under the cursor means;
- Enter shows the plan on a review screen, and a second Enter writes it. Ctrl+C cancels and writes nothing.

The menu draws on the terminal's alternate screen, so your scrollback keeps only the plan and the result. At 100 columns or more the frames stand side by side; narrower, you see one at a time. Below 40×16 you get the plain view, as before.

Without a terminal nothing changes: configure prints the view, and `--set`, `--json` and `--dry-run` work as in 0.30.1.

## Model lists from each harness

- **Claude Code** offers the aliases its Agent tool takes: `fable`, `opus`, `sonnet` and `haiku`. With `ANTHROPIC_API_KEY` set, each alias also names the newest model of its line. There is no free-text entry: Claude Code refuses any other value when it spawns the agent.
- **Codex** offers its own list of models, in its own order and with its descriptions, from Codex's model cache. It also offers "type a name…".
- **When a list is read.** Only when you open a model list and the kept list is more than a day old, or when you choose "refresh the list". That is one read, of at most 3 seconds, in the background. Claude Code's list asks the Anthropic API, only with a key, and at `ANTHROPIC_BASE_URL` when that is set. Codex's list is refreshed by Codex's own CLI, with Codex's login. Nothing is read without a terminal, under `--json`, with `--set`, under `CI` or inside an agent session.
- **The cache.** A list is kept for a day in `~/.cache/projectstore/models/`: model names and descriptions only, never a key. It is safe to delete at any time.
- **A model off the list** is still written as typed, now with a note on its plan row saying why it may not run. `--json` carries the note as the plan item's `note`. Plan items with no note are unchanged.

`agents configure` does not read the lists, and prints what it printed before.

## Upgrading

Nothing migrates. An overlay that holds a model outside the list is left as it is; the menu marks it "not in the list". To keep the menu from asking Anthropic, unset `ANTHROPIC_API_KEY`; the aliases stay.

From npm, from a terminal in your project:

```
npx projectstore@0.30.2 upgrade
```

Codex's registration is per machine:

```
npx projectstore@0.30.2 upgrade --harness codex
```

From the git marketplace, in Claude Code:

```
/plugin update
```

Then restart the agent.

Codex stays **experimental**, as [docs/harnesses.md](https://github.com/SmartAndPoint/ProjectStore/blob/main/docs/harnesses.md) defines it.
