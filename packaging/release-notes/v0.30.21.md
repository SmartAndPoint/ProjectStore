# v0.30.21 — write the backlog from a terminal, see how work flows, keep specs in trees

This release has 24 changes (#176 is a small fix to #175). You can now create initiatives, epics and stories, and set their fields, with plain verbs and no agent session. A new `flow.md` page and an `export` verb show how stories move. Specs can form trees, and doctor checks them against the code. The dashboard's page can hand a story over and reorder the backlog, shows a story's pull requests, and speaks plain words. The band shows your WIP against your limit.

```
npx projectstore@0.30.21 dashboard
```

## The dashboard

**Hand a story over** (#156). Open a story that someone holds and use **Hand over**. You give the other person and a reason. The page shows ProjectStore's `handover` plan for that one story, with a warning when the person who takes it goes over their WIP limit. Your click commits the change on the same batch branch as a move. Every write on the page now draws its dialog from one table in the server, so `move` and `handover` look the same.

**Reorder the backlog tree** (#166, #175). The tree draws each group in the order the new `rank` verb keeps: an epic's open stories, or the epics of one initiative. While the page can write and the search box is empty, a row has a grip. Drag it inside its group, or select it and press Alt+↑ or Alt+↓. A reorder that writes one file is saved at once, and the row stands in its new place. A reorder that must also number other rows asks first and says how many. If saving fails, the row goes back and a note says why. A row placed by hand gets a small ⇅ mark. A drop outside the group writes nothing.

The board, the list and My work now sort by priority, then by title. The `rank` field no longer orders them. The list's sort "Backlog order" is now called "Priority"; its key in saved views and in the address is still `order`.

**The Code block** (#167). When you open a story, the page shows its pull requests, each with a label for how it is tied to the story. Only two ties are real links: the story's own `external_refs.pr`, and a `Closes-story:` line that `follow` would count. A title, a number in the text, or commits that touched the story's code paths are shown apart, as leads. When you open a spec, the page shows its contracts grouped by the day of their last change, and what touched the spec's files since. If `gh` is missing or logged out, the block says the pull requests are unknown and still shows the commits.

**Plain words** (#175, #176). The page now talks to a product manager. Some examples:

- The strip on top says "1 change not published yet", with **Publish for review…** (Send) and **Discard changes…** (Discard). The branch, the commit count and the pull request number are under **Details**.
- The yellow `gh` warning is gone from the top of every view. It shows only in the Publish dialog and in the Code block, as one advice by its reason.
- **Kept branches** is now called **Kept aside**. The ⌘K entry "Fetch the vault's repository again" is now "Get the latest backlog".
- Board and My work count open stories only. Backlog and Initiatives show no number.
- An epic still marked `planned` with work started reads "In Progress".
- One click anywhere on a tree row opens the item.

**Your name.** The page now starts with the binding's `default_author` as your name. You choose another under **Your name** at the foot of the menu, and the browser keeps it per project. A name you chose before this release is not read, so it resets once (see Upgrading).

**A copy that is not from npm fetches no released page** (#154). A core with main's code under a release number could pass as an npm copy and fetch the page released for that number. This happened when you ran setup from a checkout, ran a packed checkout with `npx`, or installed the core from git. These copies now refuse, as a checkout already did. Only clear evidence refuses: everything else still fetches the page.

## Backlog verbs

These verbs all work the same way. Bare, they print the plan and write nothing. With `--write` they ask at a terminal, write, record the write in the session's record, and refresh the derived views. None of them has an MCP tool.

**Initiatives** (#155, #157). A new kind, `initiative`, sits above the epic, in a new `initiatives/` folder, with a template in six languages, a guide and a `/projectstore:initiative` command. Its status records only the decision: proposed, accepted, rejected or deferred. An epic joins one with `initiative: "<slug>"` in its frontmatter. Create the initiative, put an epic under it, then record the decision (`accepted` needs an epic that names the initiative first):

```
npx projectstore create initiative "Faster onboarding" --write
```

```
npx projectstore epic PS-CORE --initiative faster-onboarding --write
```

```
npx projectstore initiative faster-onboarding accepted --reason "groups the onboarding epics" --write
```

`initiative` also edits the title, owner and priority. `epic --initiative ""` clears the link. The link graph gets a new edge kind, `initiative-contains`.

**Create, and the not-reviewed mark** (#158). `create initiative|epic|story` writes the same file the agent command writes, from its template. A story also gets its row in the epic's Stories table, and the board is rebuilt. It never overwrites a file. What it writes is marked not reviewed (`written_by_verb` and `review_status: pending`). A story's plan gate runs the review on a marked file first, and `reviewed <path> --write` clears the mark.

```
npx projectstore create story PS-CORE "Faster login" --write
```

**The epic's Stories row** (#133). The story command now adds the new story's linked row to its epic's Stories table at create, under the same approval. The six epic templates lose their placeholder row: the epic rule counted it as an open row, so it never closed such an epic by itself.

**Rank** (#159). `rank` orders open work by hand, apart from priority: an open story among the open stories of its epic, or an epic among the epics of its initiative. It writes only a `rank:` line in each file whose value changes. It moves no date, so a story's age does not reset. If another writer changed a rank meanwhile, it stops and puts back what it wrote.

```
npx projectstore rank story PS-CORE/story-faster-login --before PS-CORE/story-sso --write
```

**Groom** (#141). `groom` is a weekly pass. A story that sat in ToDo past `flow.age_days.todo` goes back to the backlog, with the reason in its Status log. The pass lists one-story epics, counts active epics against `flow.active_epics_max`, and records its date in `flow.groomed_at`. `/projectstore:groom` does the same and then asks the librarian which epic each one-story epic could join; the librarian changes nothing.

```
npx projectstore groom --write
```

## Spec trees

A spec can now name the spec it is part of, with `parent:` in its frontmatter (#161). The specs then form trees: an overview at the root, components under it, details under those. Nothing changes in a vault with no `parent:`. The graph gets a new edge kind, `spec-part-of`, and `graph lineage` walks a tree:

```
npx projectstore graph lineage specs/<root>.md --kind spec-part-of --depth 3
```

**A spec owns code** (#162). An active spec in a tree can name its code with `code_refs:`, as a story does. Doctor then checks that a child's code sits inside its parent's, and that each ref covers a tracked file. The planner asks which specs own a file before it places a change.

**Out of date specs** (#163, #164). Doctor warns when a spec's code changed on the trunk after the spec was last changed, checked, or closed over by one of its stories. It also warns when an overview cites a child's contract that changed later, or misses a newer child. If you read the spec against the code and find nothing to change, add a `checked` marker under the contract:

```
> checked 2026-11-20 by story-x: compared the retry limit with scripts/retry.mjs
```

**The tree view** (#168). A new derived page, `spec-tree.md`, shows each tree as a diagram and a nested list. Create it once; later reconciles keep it fresh:

```
npx projectstore reconcile --write --only spectree
```

Once it exists, a session starts with one line about the trees.

#160 moves the text grammar and the skeleton renderer out of `lib.mjs`. Nothing changes in behaviour.

## Flow

**`flow.md`** (#165, #170). A new derived page beside the kanban. It shows WIP per person against their limit, the date each open story entered its status, stories created and closed each week, the cumulative flow as a Mermaid chart, the cycle time (the median days from start to close), and the epics in progress where no story changed status for `flow.age_days.epic_idle` days. That key is new; set it with configure. The page is dated by the newest date a story carries, not by the clock, so a rebuild on another day writes the same bytes. Create it once:

```
npx projectstore reconcile --write --only flow
```

**Export** (#172). `export` prints the same flow data as one JSON document, for another tool: every story and epic, every status change from the Status logs, and the counts doctor and `flow.md` show. It writes nothing and runs no git. Email-shaped assignees are masked, but titles, Status log reasons, actors and the project's full path are printed as they are. Review them before you publish the file.

```
npx projectstore export > flow-export.json
```

**Close-refs** (#169). A story's close now writes the `code_refs` it was given. The new read-only verb `close-refs` finds them: from the story's pull request with `gh`, else from the reviewer's last `code_refs:` line, else from the commits since the story started (marked "not verified"). The story command shows them in the close preview, adds them to the story, and adds the ones the epic does not cover yet to the epic's `code_refs`.

**The band's WIP** (#173). In Claude Code, the band's head row ends with `WIP <n>/<limit>` for the binding's `default_author`: dim under the limit, yellow at it, red over it. It is the same count as doctor, `next` and `flow.md`. The count can lag a hand edit until the next write or session start.

## Attribution

Doctor's spec acceptance check now reads a qualified id, `<epic-id>/<story-id>`, and ignores text after the ids on the same line, such as `— stories: X — evidence: y` (#132). Before, both cases gated no story. The `ambiguous-attribution` warning now names the real entries, so you can paste its advice back.

## Doctor

Doctor has 24 new findings. Most of them appear only when you use their feature. The flow ones can appear at once in a vault that has a `flow` policy, and `rank-tie` at once where two items of a group already hold the same `rank:` (see Upgrading).

- Initiatives: `initiative-links`, `initiative-status`, `initiative-decision`.
- Create: `verb-mark` (info) for each file still marked not reviewed.
- Rank: `rank-tie` (info).
- Groom: `grooming-due` (info), `epic-single-story` (info), `active-epics-over-cap` (warn).
- Spec trees: `spec-parent`, `spec-cycle`, `spec-outside-tree`, `spec-code-outside-parent`, `spec-code-empty`, `spec-undescribed`, `spec-tree-git`, `spec-stale-code`, `spec-stale-unknown`, `spec-stale-parent`, `spec-child-unlinked`, `checked-form`, and `spec-tree` for the view.
- Flow: `flow-view` for the page, `flow-cycle-time` (info), `epic-idle` (warn).

A `flow` block that holds only `groomed_at` now reads as unset, in doctor and in `next`.

## What it runs, writes and sends

- **It runs `gh` during a story's close.** `close-refs` runs `gh repo view --json url`, `gh pr view` for the pull request's files, and `gh api …/pulls/<n>/files` when there are more files than `gh pr view` gives. It also runs `git rev-parse --show-prefix`, `git merge-base --is-ancestor` and `git log`.
- **The dashboard reads the project's code.** For the Code block the page runs `git log`, `rev-list`, `rev-parse`, `show` and `diff` in your project's repository. It never fetches there, and `GIT_NO_LAZY_FETCH=1` stops a partial clone from fetching objects. It runs one `gh pr list` for up to 1000 pull requests and keeps it for 10 minutes. The descriptions stay in the server's memory; they are never written to a file or sent to the page. This read is a new POST route, `/api/code`, with the same token and `Origin` check as the write routes.
- **The page runs `handover` and `rank`** in its clone, beside `move`.
- **Doctor reads the trunk's history only in a vault with a spec tree** that names code: the trunk's `git log` (the remote's default branch, else `main` or `master`) and `git ls-files`. Without a tree no git process starts for these checks.
- **It writes `.projectstore/state/wip.json`** in Claude Code, with the band on, a `default_author` and a `flow` policy: the person's name, their in-progress and review count, how many wait to be closed, and their limit. SessionStart, `move`, `follow`, `handover` and `session refresh` write it, only when a number changes. It is machine-local, never in the vault, and it is removed when the vault has no `flow` policy.
- **It writes in the vault only after your approval or `--write`:** the new verbs' files and lines, `flow.md` and `spec-tree.md` once you create them, `code_refs` at a story's close, and `flow.groomed_at` in `.projectstore.json`.
- **Setup marks a local copy.** When setup runs from a checkout, a packed checkout or a git install, the npm registration gets `origin: "local"`. A copy from the registry writes the same six keys as before. A later run from a registry copy with the same bytes removes the mark.

ProjectStore still sends nothing of its own. The README, the privacy page and llms say the same.

## Upgrading

Nothing migrates. What changes when you upgrade:

- the vault gets no new file until you create one. The `initiatives/` folder, `flow.md` and `spec-tree.md` appear only when you create them;
- in a vault with a `flow` policy, doctor may show new info and warn lines at once: `flow-view` (no `flow.md` yet), `flow-cycle-time` when `flow.window_weeks` is set, `grooming-due` when `flow.grooming_days` is set (no pass is recorded yet), and the epic counts when `flow.active_epics_max` is set;
- a done story can get a new `spec-acceptance` issue, when one of its items had text after the ids and is still unchecked (#132);
- on the dashboard, a name you chose before is not read. The page starts once with the binding's `default_author`, or with no name when the binding has none. Choose your name again under **Your name**;
- the board, the list and My work no longer order by `rank`. Two items of one group that already hold the same `rank:` value get `rank-tie` (info) at once;
- an epic made from an older template still has the placeholder row `[story-001]` in its Stories table. The epic rule counts it as an open row, so it never closes that epic by itself. Remove the row by hand;
- `.projectstore/state/wip.json` appears at the next session start in Claude Code, when the band is on and the vault has a `flow` policy. A writing verb run from a terminal may write it too;
- the dashboard's clone in `.projectstore/state/dashboard/` stays as it is, with its open batch and kept branches;
- an npm copy fetches the dashboard's package for 0.30.21 on its first `dashboard` run, into `dashboard/0.30.21/` beside the old version's folder, which stays.

The commands, agents and hooks change, so an installed copy needs the upgrade to get them.

From npm, from a terminal in your project:

```
npx projectstore@0.30.21 upgrade
```

Codex's registration is per machine:

```
npx projectstore@0.30.21 upgrade --harness codex
```

From the git marketplace, in a Claude Code session: open `/plugin manage` and choose **Update now** on projectstore, then run `/reload-plugins` to load it. Or, from a terminal, then restart Claude Code:

```
claude plugin update projectstore@SmartAndPoint
```

The git marketplace serves main, so a copy installed or updated since these changes merged may already have them under the number 0.30.20. For it, this release changes the number.

The agents block stays v5, and the MCP tools are the same nine. The `lineage` tool's description now names the sixth kind, `spec-part-of`.

## Not seen live yet, and known gaps

- The band's WIP segment in a live terminal and on Desktop, the SessionStart write on a slow synced vault, and no flicker on Desktop. The band is a hook, so this shows only in the installed plugin.
- The librarian's new "Epic merges" lens, which `/projectstore:groom` uses. The installed plugin carries the older agent file until the upgrade.
- Obsidian drawing `flow.md`'s chart, and `spec-tree.md` in Obsidian and on GitHub.
- On the dashboard: a drag with a real mouse (the check used keys and script events), and a pull request on GitHub from this build. Hand over and reorder were checked against a local bare `origin` with a stub `gh`.
- A copy that is not local still fetches the page in these cases: a global install of a tarball, a tarball installed by pnpm, Yarn or Bun, a tarball given by URL, and an install through a symlinked prefix.
- `spec-stale-code` can warn on a spec when a shared file changes. A 30-day replay on this project's own vault found one such hit.
- Windows: the dashboard's page still reads the vault and changes nothing. It was checked in tests only.
