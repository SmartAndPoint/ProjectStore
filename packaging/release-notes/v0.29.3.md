# v0.29.3 — A band above the prompt, and terminal output you can scan

In Claude Code, ProjectStore now draws a band above the prompt. The CLI's terminal output is redrawn, doctor groups its findings by cause, and install, upgrade and uninstall lose several rough edges.

## The band above the prompt (Claude Code, experimental)

Above the prompt, for this session, the band shows:
- `[PS#0.29.3]` and the epic the session works on, with its goal;
- the epic's stories by stage, as a bar with counts;
- the story in hand;
- the ProjectStore agent at work, with the model and effort its own requests name.

It hides while a question is open. While it draws, the status line leaves out its 📚 line and keeps the rest of your HUD; when the band stops, the line comes back by itself. On a Claude Code that does not load hooks modules, nothing changes. Claude Desktop draws the band too, with the bar as a grid.

The band is on by default. A new command switches it, pins an epic for sessions with none of their own, and says why it is not drawing:

```
/projectstore:bar status
```

```
/projectstore:bar off
```

Codex has no band, and its bar skill says so.

## Output you can scan

- **Plans** are grouped by agent, one aligned row per change, and end with one confirm: `◆ Apply N changes? [Y/n]`. When a host command fails, the run says how it ended.
- **Doctor** groups its report by cause, with one fix line per cause.
- **Help and status** put commands on their own lines and fit in 80 columns. Status groups the stories in progress by epic.
- `NO_COLOR=1` turns colour off and `PROJECTSTORE_ASCII=1` draws every glyph in ASCII. `TERM=dumb` does both.

Every `--json` envelope is unchanged.

## Install, upgrade and uninstall

- **No downgrade.** A run from a package older than a copy the project already runs never writes over that copy. If the newer release is published, the run stops and names it; otherwise it leaves the newer copy alone and says why.
- **A newer release is announced** once per terminal run of `install` or `upgrade` from the npm package. It never prints under `--json` or `CI`. `PROJECTSTORE_NO_UPDATE_CHECK=1` turns it off.
- **Moving a checkout from the git marketplace to the npm install** is a plan row of its own (`⇄ switch`), and happens only when you confirm it at a terminal. Without one, `install` and `upgrade` refuse it. `uninstall` turns the git copy back on.
- **The agents block is planned once per run**, for every agent in it. A bare `uninstall` now covers every agent the project uses, and a Codex-only uninstall no longer hides the block from Claude Code.
- **The status line of an npm registration stays put.** On Claude Code 2.1.293 and later, every session start re-pointed the line that `install` had wired. It no longer does.
- **Codex.** Inside a Codex session, `install` and `upgrade` leave the Codex registration for a terminal, and say so. `uninstall --global` now removes the registration; before, it exited 0 and removed nothing.
- **A verb refuses an argument it does not take,** naming it, instead of running as if it were not there.

## Vaults

`init` creates a whole vault in one step: the folder, its git repository, the layout's folders and their README indexes. No `mkdir` first:

```
npx projectstore@0.29.3 init ~/vaults/new-project
```

`scaffold` is now a CLI verb too. With `--write` it adds the layout's missing folders to a bound vault and never rewrites a file.

## Upgrading

Nothing migrates, and nothing needs a step beyond the update. The binding, the agents block, the overlays and the vault are untouched. A project with no band setting reads as on.

Claude Code from the git marketplace: update, then start a new session.

```
/plugin update
```

Claude Code from npm, from a terminal in the project:

```
npx projectstore-claude@0.29.3 upgrade --project "$PWD"
```

Codex: upgrade, then restart Codex and approve the ProjectStore hooks if it asks.

```
npx projectstore-codex@0.29.3 upgrade --project "$PWD"
```

Codex stays **experimental**, as [docs/harnesses.md](https://github.com/SmartAndPoint/ProjectStore/blob/main/docs/harnesses.md) defines it.
