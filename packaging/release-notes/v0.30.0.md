# v0.30.0 — The README, docs and site lead with setup

A documents release. `setup` shipped in 0.29.4, and from 0.30.0 the README, the docs, the site and the npm pages lead with it. No hook, command, skill, agent or template changed; only a few texts a run prints did, all listed below.

## The way in

The README's Install section now starts with setup, from a terminal in your project:

```
npx projectstore setup
```

If you prefer a global command:

```
npm install -g projectstore
```

```
projectstore setup
```

Behind a registry mirror (often a company's), `npx` may run an older release that has no setup. Name the version, and if that is not enough, the public registry:

```
npm_config_registry=https://registry.npmjs.org npx projectstore@0.30.0 setup
```

Upgrading and Uninstalling use the same package and need no per-agent package. The README now agrees with doctor: a project on the pre-0.28 layout is read through 0.30.

## The per-agent packages

`projectstore-claude` and `projectstore-codex` are now described as release artifacts, and their npm pages point to setup. Setup fetches the Codex one by itself, so nobody needs to type its name. A shell asked to install for another agent now names the core's command. The install steps that `plan --verbose` and `--json` report for each agent now end with the core's install, and link the README's Install section.

## A missing Codex version names the public registry

When the registry has no Codex plugin at the version you run (a mirror that is behind, or the minutes after a release), the refusal now also prints the same run against the public registry, alone on its line. It is left out when the registry already is npm's own.

## Site

projectstore.dev, in all eight languages, now has one install tab, "In a terminal", with setup.

## Upgrading

Nothing migrates. As in every release, the status-line launcher reads stale until the upgrade re-stamps it.

From npm, from a terminal in your project:

```
npx projectstore@0.30.0 upgrade
```

Codex's registration is per machine. To upgrade it even in a project where no Codex session has run yet:

```
npx projectstore@0.30.0 upgrade --harness codex
```

From the git marketplace, in Claude Code:

```
/plugin update
```

Then restart the agent. A project on the pre-0.28 layout is still read through the fallback until 0.31; doctor names the command that moves it.

Codex stays **experimental**, as [docs/harnesses.md](https://github.com/SmartAndPoint/ProjectStore/blob/main/docs/harnesses.md) defines it.
